# Architecture

## Scope

This repository is a public profile and presentation package, not a product runtime. It contains the README, six Markdown case studies, SVG architecture and hero artwork, screenshots, a content-rights notice, and a small Python generator for the SVG diagrams. The products described by the case studies have private source repositories outside this checkout.

## Content and asset flow

- The README is the profile entry point and links to the case studies and a separate public code repository.
- Each case-study Markdown file contains a problem statement, architecture description, design decisions, evidence dates, limits, and links to local presentation assets.
- The diagrams are generated by the existing assets/diagrams/build.py script from its in-file specifications. Generated light and dark SVG files are tracked beside that source.
- Screenshots and diagrams are static assets. Captions describe whether an example is synthetic or sample data.
- Git stores and versions this publication. There is no product database, local service, package manager, application test runner, authentication flow, or runtime model/provider call in this repository.

## Product architecture described by the profile

The case studies describe different systems, not one integrated product. Their documented boundaries include:

- Conductor: an advisory assistant is separate from a deterministic action worker and human review.
- GraphForge: assistant-drafted typed blueprints compile into a typed graph representation; the described runtime supports checkpoints and human interrupts.
- Mandate Guard: a parser proposes a structured restriction; deterministic code evaluates holdings and a reviewer sees source-linked evidence.
- Redactor: an assurance step is described as transforming supported files or refusing unsupported ones; the profile asserts hard-offline behavior.
- Relay: local speech recognition is described separately from optional provider-backed cleanup, with an offline policy gate.
- Enterprise automation: related tools handle artifact review, release generation, OCR, and uncertainty routing; the case study says they are not one deployed customer platform.

These are descriptions published in the case studies. This profile repository does not execute or independently qualify the private product behavior.

## Trust boundaries and evidence limits

The public trust boundary is this repository's text and assets. Private source is not copied into it. A screenshot can illustrate a screen but cannot prove a test passed, that a network was blocked, or that a customer system is connected. The dated evidence rows are self-contained publication records unless the case study points to a primary artifact; most do not include a source commit or test receipt.

The SVG generator writes presentation files into the same asset directory. When a diagram changes, edit its specification and regenerate the outputs through that existing script; do not hand-edit generated SVGs.

## Failure modes and trade-offs

The profile can become stale when a product source changes without a corresponding update to the dated case study. Markdown rendering can vary across hosts, and broken relative links can make screenshots disappear. There is no app build or test suite here to detect behavior changes in the described products.

This publication keeps private product code out of the public profile and uses synthetic or sample examples. A full product demonstration requires a separately authorized checkout of the relevant source, a specific commit, its own test evidence, and a safe offline environment. This repository alone cannot support a production-readiness or customer-acceptance claim.
